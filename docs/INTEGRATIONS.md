# Интеграции: платформы и источники

> **Важно.** Из среды разработки были недоступны API Telegram и Meta и сайты казахстанских СМИ. Адаптеры написаны по официальной документации (актуальность — сентябрь 2026) и проверены на **подменённых ответах** (`httpx.MockTransport`), а не на живых сервисах. Перед запуском выполните чек-лист в конце документа.

Первый этап: **Telegram, Instagram, Facebook** (WhatsApp исключён ТЗ). Публикация — только через официальные API; пароли внешних платформ не запрашиваются и не хранятся (только токены, шифрованные AES-256-GCM).

## Telegram (Bot API)
* Создайте бота у @BotFather, добавьте его **администратором канала с правом публикации сообщений**.
* В «Управление → Аккаунты» укажите идентификатор канала (`-100…` или `@username`) и токен бота. Проверка подключения: `getMe`, `getChat`, `getChatMember` — требуется статус администратора с правом публикации.
* Методы: `sendMessage` (текст 1–4096, HTML `<b> <i> <u> <s> <code> <a href>`), `sendPhoto` (подпись до 1024), `sendMediaGroup` (2–10). Ошибка 429 учитывает `retry_after`.
* **Идемпотентности у Bot API нет и прочитать историю канала бот не может** → при неизвестном исходе (таймаут после отправки, 5xx) система **не повторяет** отправку сама: нужна ручная проверка канала.
* **Статистики постов канала Bot API не отдаёт** (нет просмотров/пересылок): собираем число подписчиков; просмотры вносятся вручную или импортом («Аналитика → Ручной ввод / импорт»).

## Instagram (Graph API, публикация контента)
* Нужен **Business/Creator-аккаунт**, привязанный к странице Facebook; токен с правами `instagram_basic`, `instagram_content_publish`, `pages_show_list` (+ `instagram_manage_insights` для метрик). Доступны два пути входа (Facebook Login / Instagram Login) — система работает с идентификатором IG-аккаунта и токеном.
* Поток: `POST /{ig-id}/media` (контейнер; для карусели — дочерние контейнеры + родительский `CAROUSEL`) → опрос `GET /{container}?fields=status_code` (`IN_PROGRESS|FINISHED|ERROR|EXPIRED|PUBLISHED`) → `POST /{ig-id}/media_publish`. Прогресс (id контейнеров, `media_id`) сохраняется после каждого шага, поэтому повтор не создаёт дублей.
* Лимит публикаций через API — **100 за скользящие 24 часа** (карусель считается за 1), проверяется через `content_publishing_limit` до загрузки; в разных источниках встречается и значение 50 — система читает фактическую квоту у платформы. Карусель — до 10 элементов. Принимается **JPEG** (PNG/WebP — нет): карточки генерируются в JPEG.
* **Изображения скачивает сам Instagram по публичному URL** → нужен доступный из интернета HTTPS-адрес (`SMI_PUBLIC_URL`); приложение отдаёт файл по неугадываемому токену `/media/<token>.jpg` **только для публикаций в работе** (запланировано/публикуется/опубликовано).
* Reels: 9:16, H.264/HEVC, ≤90 с, нужен готовый видеофайл (`video_url`); генерация видео не реализована. Stories — не реализованы (только для бизнес-аккаунтов).
* Собственного планировщика у IG нет: запланированные посты хранит и отправляет система.
* Метрики (каждая запрашивается отдельно, отсутствующие — «нет данных»): `reach`, `views` (с апреля 2025 заменил `impressions/plays/video_views`), `likes`, `comments`, `shares`, `saved`, `total_interactions`; данные приходят с задержкой до 48 ч.

## Facebook (страницы)
* Токен **страницы** с правами `pages_manage_posts`, `pages_read_engagement` (для метрик); публикация — `POST /{page-id}/feed` (текст) и `/{page-id}/photos` (изображение). Личные профили и группы не поддерживаются Graph API.
* Сверка неизвестного исхода — по последним постам страницы (совпадение текста), «не найдено» признаётся только спустя 10 минут.
* Метрики: `post_media_view`, `post_total_media_view_unique` (метрики вида `post_impressions_unique` удалены Meta), реакции/комментарии/репосты.

## Версия Graph API
`SMI_META_GRAPH_VERSION=v26.0` (выпущена 29.07.2026; v25.0 действует до 29.07.2028). У Meta регулярно меняются метрики и сроки депрекаций — сверяйтесь с changelog; ошибки отдельных метрик не ломают сбор.

## OAuth Meta (необязательно)
При заданных `SMI_META_APP_ID/SECRET` доступен поток «Управление → OAuth Meta»: подписанный `state` против CSRF, обмен кода на долгоживущий токен, перечень страниц и IG-аккаунтов. Проверен только на моках; основной путь — подключение по токену.

Официальные домены для определения «первичного источника» — в `defaults/gazetteer.yaml::official_domains` (gov.kz, akorda.kz, nationalbank.kz, stat.gov.kz, who.int, federalreserve.gov, nasa.gov, …). Добавить свой источник или домен можно конфигурацией (`SMI_CONFIG_DIR`/интерфейс) без правки кода.

**Правовые рамки:** опрос уважает `robots.txt` и интервалы; платные источники — только заголовки/анонсы; сторонние изображения не скачиваются и не републикуются (используются собственные карточки); в материалах источники указываются.

## Чек-лист перед запуском в бою
1. Для каждого источника: «Система → Источники → Опросить» — статус `ok`, свежий «последний материал»; отключите/замените нерабочие.
2. Telegram: подключите тестовый канал, опубликуйте тестовый пост, проверьте «Сверку» (должна честно ответить «unknown» при потере ответа).
3. Instagram/Facebook: тестовые аккаунты; проверьте публичную доступность `SMI_PUBLIC_URL/media/…`, квоту `content_publishing_limit`, метрики (какие недоступны в вашем приложении Meta).
4. Проверьте права приложения Meta (App Review для `instagram_content_publish`, `pages_manage_posts`).
5. Выполните `smi-agent backup restore-test` и `smi-agent health`.
