# Архитектура

Стек: Python 3.11, FastAPI (синхронные эндпоинты в пуле потоков), SQLAlchemy 2 (SQLite для одного узла, PostgreSQL для прода), Pydantic, httpx, feedparser, Pillow, cryptography. Интерфейс — ванильный JS без сборки (ES-модули, строгий CSP: `script-src 'self'; style-src 'self'`).

Все сервисы собираются в один контейнер зависимостей (`container.py`) и используются одинаково API, воркером, CLI и тестами. Время берётся из `Clock` (в тестах — `FakeClock`).

## 2. Поток данных и правила транзакций

```
Source ─poll→ Article(+features) ─cluster→ Event(+carriers, flags, features) ─score→ Trend Score/phase
   ↓                                                                     ↓
FunnelRun: pool→s50→s15→s10(Verification)→s5 → Proposal(card) ──команда──→ Content(FactBase, PlatformVersion×3, MediaAsset, CheckReport)
   ↓                                                                     ↓
Publication(state machine) ─claim→ adapter.publish ─→ PublishAttempt ─→ MetricSnapshot ─→ ForecastRecord/PerformanceStat ─→ ProfileFeature
```

Жёсткие правила (проверяются тестами):

1. **Сетевые вызовы не выполняются внутри транзакции записи.** SQLite допускает одного писателя; `Database.session(write=True)` начинает `BEGIN IMMEDIATE` и считает глубину транзакции потока. LLM-вызов внутри неё вызывает `RuntimeError` (`LlmService.run_json`). Создание материала — трёхфазное: чтение → генерация (LLM) → короткая запись (`ContentService.prepare/persist`).
2. **Публикация** тоже трёхфазна: (A) атомарный захват + предполётные проверки, (B) вызов платформы без транзакции, (C) запись результата с проверкой `claim_token`.
3. **Журнал аудита** пишется в той же транзакции, что и действие; цепочка хешей сериализуется блокировкой строки `audit_head`.

## 3. Алгоритмы

### 3.1 Нормализация и признаки (`ingestion/`)
Канонический URL (без `utm_*`, `fbclid`, фрагментов, `www.`, завершающего `/`; ключ дедупликации — SHA-1 без схемы). HTML очищается (скрипты, баннеры, «Читайте также», трекинг-пиксели). Даты приводятся к UTC с учётом часового пояса источника; будущие даты обрезаются до «сейчас». Из текста извлекаются: сущности (с кросс-языковым «скелетом»: Gates/Гейтс → `gts`), числа с единицами и масштабом («7,8 млн тонн» ≡ «7.8 million tonnes»), даты, цитаты (≥ 4 слов), ссылки на другие источники («передает X со ссылкой на Y») и флаги качества (кликбейт, реклама, оговорки «якобы», мнение, prompt-injection).

### 3.2 События и независимость источников (`events/`)
* Кандидаты-события ищутся по инвертированным индексам (стемы, сущности, числа), затем считается `pair_score` двумя путями: **лексический** (TF-IDF на языке материала + заголовок + сущности + числа + цитаты) и **языконезависимый** (сущности + числа + даты). Порог присоединения калибровался на корпусе «одно событие / та же тема, другое событие» (худшая пара «то же событие» 0.34 против лучшей «другое» 0.15).
* У каждого материала есть **происхождение** (`origin`): если он ссылается на другое издание/агентство — origin ссылки, иначе — группа издания. `n_independent` = число происхождений с собственным материалом (если их нет — число «заявленных» по ссылкам). Отношения: `original / independent / reprint / translation / update / duplicate`.
* Поэтому 40 перепечаток «Global Wire» — это 1 независимый источник и не ускоряют «скорость роста».
* После присоединения проходит слияние событий, оказавшихся одним; порядок поступления материалов не влияет на результат (тест с перестановками).

### 3.3 Trend Score (`scoring/trend.py`)
`TrendScore = 100 · Σ wᵢ·cᵢ / Σ wᵢ`, затем штрафы (кликбейт, реклама, оговорки, мнения, prompt-injection, повтор). Все компоненты ∈ [0, 1], у каждого есть объяснение на русском.

| Компонент | Вес по умолчанию | Суть |
|---|---|---|
| freshness | 0.10 | затухание с периодом полураспада 14 ч (по первой и последней публикации) |
| independent_sources | 0.12 | насыщающая функция от Σ надёжность·вес независимых источников (первичные ×1.25, «по ссылке» ×0.5) |
| velocity | 0.14 | независимых источников в час за окно 2 ч и ускорение; при одном источнике = 0 |
| scale | 0.07 | маркеры масштаба, крупные суммы/числа, число стран-источников |
| novelty | 0.06 | маркеры новизны − «продолжение», с учётом повтора (§51) |
| significance | 0.10 | max(значимость для КЗ, мировая значимость·0.92); оба значения сохраняются |
| practical_value | 0.10 | прикладные маркеры и категории, влияющие на повседневную жизнь |
| audience_interest | 0.06 | профиль (бета-апостериор по теме/подтеме/гео), нейтрально 0.5 без данных |
| discussion | 0.04 | маркеры спора/реакции, цитаты, число источников |
| fact_sufficiency | 0.06 | факты, числа, даты; штраф за оговорки; платные источники — анонс |
| source_quality | 0.06 | взвешенная надёжность независимых источников + первичный источник |
| feasibility | 0.04 | достаточно ли данных для оригинального материала |
| historical | 0.05 | результативность прошлых публикаций по теме (PerformanceStat) |

Веса и окна настраиваются в `ProjectSettings.scoring` без правки кода. Фазы: `emerging / rising / peak / fading / stale` (по возрасту, скорости и ускорению).

### 3.4 Воронка (`funnel/service.py`)
* **Этап 1 (→50):** отсев устаревшего, ниже порога значимости (`min_trend_score`), рекламы, заблокированных тем профиля, недавно отклонённых, уже опубликованного (кроме «новой стадии»). Отбор жадный с **мягким гео-приором**: `adj = score · (1 + s·(целевая_доля − текущая_доля_корзины))`; Центральная Азия относится к «КЗ». Слабые темы ради квоты не добавляются.
* **Этап 2 (→15):** кликбейт, реклама, слухи при одном источнике, мало фактов, незначительность, повторы, prompt-injection, дубли между событиями; причины пишутся в `FunnelItem.reasons`.
* **Этап 3 (→10):** `VerificationService` — первичный источник (официальный домен/источник), независимые подтверждения, согласованность чисел (противоречия в заголовках), цитаты, оговорки, факты vs интерпретации. Статусы: «подтверждено» / «подтверждено несколькими источниками» / «требуется дополнительная проверка» / отклонено. Допускается не более `max_unverified_in_stage3` непроверенных — с предупреждением.
* **Этап 4 (→5):** разнообразие по направлениям (КЗ · ИИ/технологии · авто/транспорт · экономика/бизнес · наука/мир/необычное — данные в `defaults/taxonomy.yaml`): сначала лучший кандидат в каждом направлении (направления с наименьшим числом кандидатов первыми), затем лучшие из оставшихся (≤2 из одной категории); порог значимости действует и здесь.
* **Замена** берёт кандидата из резерва (этапы 10/5 того же запуска), иначе честно отказывает.

### 3.5 Генерация (`content/`)
1. **FactBase** — единственный источник утверждений: проверенные факты с поддержкой (сколько независимых источников), числа, цитаты с авторами, даты, неизвестное, первоисточники. Факты с prompt-injection исключаются.
2. **Бриф** (язык, тон, угол, акцент, объём, стиль из правок) → **LLM** (`core_draft`, затем по платформам) либо **эвристическая заготовка** (целые предложения с атрибуцией, не выдаётся за оригинальный текст).
3. **Защита от галлюцинаций** (`validate_generated`): каждое число — из базы фактов (±1%), цитата (≥4 слов) — из базы, ссылки — только на источники, язык совпадает, нет агитационных формулировок, нет «слишком близко к источнику» (общая фраза ≥10 слов или >12% общих 5-грамм). Нарушение ⇒ ответ отклонён, заготовка + пометка в `draft.notes`.
4. **Платформы:** Telegram (HTML, ≤4096; подпись к фото ≤1024), Instagram (подпись ≤2200, хэштеги, слайды карусели ≤10, сценарий Reels, JPEG), Facebook. Тексты пишутся отдельно, маркировка ИИ добавляется при рендере (`content/render.py`), «Проверено редактором» — после подтверждения человеком.
5. **Проверки** (`checks/service.py`): длина, HTML, числа, цитаты, ссылки, оригинальность, совпадение заголовка, атрибуция, «свои выводы не приписаны источникам», нейтральность/политика, запрещённые слова, язык, секреты, маркировка ИИ, медиа (права, формат, пропорции, метка ИИ), статус проверки события, prompt-injection, повтор, генератор. Любой `fail` запрещает публикацию; `blocks_autopilot` — автопубликацию.

### 3.6 Публикация (`publishing/`)
Состояния: Черновик → Ожидает подтверждения / Требует проверки → Запланировано → Публикуется → Опубликовано | Ошибка | Отменено (матрица переходов в `TRANSITIONS`, недопустимый переход — 409).

* **Идемпотентность:** ключ `sha256(content|platform|account|version|text_hash|n)` уникален; повторное создание возвращает ту же публикацию; правка текста отменяет подтверждения старой версии.
* **Захват:** `UPDATE … WHERE state='scheduled' AND … SET state='publishing', claim_token=…` — атомарный; тест: 6 воркеров → одна отправка.
* **Исход попытки** (`publishing/errors.py`): `not_sent` (соединение не установлено) и `rate_limited` — безопасный повтор с экспоненциальной паузой; `failed_permanent` (4xx, токен) — ошибка, при 401/403 аккаунт → «нужна повторная авторизация»; `unknown` (таймаут после отправки, 5xx) — **повтор запрещён**: запускается сверка.
* **Сверка** по платформам: Instagram — статус контейнера и `media_id` из сохранённого прогресса (повтор не создаёт второй контейнер и не вызывает `media_publish`); Facebook — сопоставление с последними постами страницы; Telegram — Bot API не позволяет доказать отсутствие сообщения ⇒ только ручное решение («Уже опубликовано» / «Повторить, я проверил»). Зависшие в «Публикуется» после сбоя процесса обрабатываются `recover_stuck`.
* **Аварийный выключатель:** уровни система/проект/аккаунт/платформа/категория; включается любым пользователем, **снимается только администратором**; проверяется в момент захвата (даже для уже запланированного) для публикаций, **подтверждённых автопилотом**; запланированные им посты в зоне действия возвращаются в «Ожидает подтверждения». Решение человека (в том числе по посту, созданному автопилотом) — ручное: выключателем автопилота не блокируется, а к тексту добавляется «Проверено редактором».
* **Автопилот:** ворота — режим `autopilot`, аккаунт в режиме `auto`, политика включена, LLM подключена, Trend Score ≥ порога, проверка фактов ≥ `multi_confirmed`, не политика/не чувствительное/не повтор/не injection, лимиты и тихие часы, все проверки `passed` и без `blocks_autopilot`. Выбор автопилота не считается сигналом предпочтений пользователя.

### 3.7 Обучение и прогноз (`learning/`, `profile/`, `analytics/metrics.py`)
Профиль — бета-распределения (α, β) по признакам (`category`, `subtopic`, `geo`, `format`, `language`, `emphasis`, `style`) с затуханием (период полураспада 90 дней). Сигналы: выбор (+1 к признакам события, слабый минус показанным, но не выбранным), отклонение, замена, «подробнее», правки текста (длина, хэштеги, эмодзи, тон), результат публикации (log-отношение к базовому уровню аккаунта, усадка по выборке). Прогноз «интерес → результат» калибруется методом наименьших квадратов по оценённым публикациям и показывается с уровнем уверенности; точность прогноза (MAE, смещение, корреляция) выводится в аналитике.

| Платформа | класс адаптера с `publish/reconcile/check_account/fetch_metrics`, регистрация в `AccountService.adapter_for`, лимиты в `LIMITS`; конечный автомат, идемпотентность, проверки и аудит общие |
| Провайдера LLM | клиент с методом `complete()` и регистрация в `llm/client.py::build_client` |
| Векторную семантику | заменить/дополнить вектор в `events/similarity.py` (интерфейс `ArtVec.tf` → эмбеддинг) |

## 6. Масштабирование
API без состояния (сессии в БД); фоновые задания — через `JobLease` (несколько воркеров безопасны); окна по времени ограничивают объём расчётов (кластеризация — только последние `dedup_window_hours`); индексы по `project_id/время/состояние`. Для роста: PostgreSQL, вынос воркера в отдельные процессы, ограничитель частоты на уровне прокси. Выбор SQLite/PostgreSQL — настройка `SMI_DATABASE_URL`; PostgreSQL в среде разработки не запускался.
